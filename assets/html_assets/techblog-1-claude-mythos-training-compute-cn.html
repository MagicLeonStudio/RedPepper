Claude Mythos 级模型
训练算力与成本深度分析

基于 NVIDIA Blackwell GPU，对 2T / 4T / 10T 总参数规模的下一代前沿 MoE 模型进行基础设施需求估算

原文 Polymath707 2026-04-09 算力架构

说 Claude Mythos 令人惊艳，那是轻描淡写了。它代表着能力上的一次阶跃式飞跃，正如 Dario 所说——上限不存在。

我们想要搞清楚，训练下一代参数级别在 2T、4T 和 10T 的模型，究竟需要多少算力和数据（各种传闻！）。话说回来，Elon 今天刚宣布他们正在训练这个级别的模型，所以这项分析来得正是时候。

方法论

我们使用估算 DeepSeek V3、ARCEE、KIMI 2.5 等模型训练成本时的公式与方法。GPU 性能数据取自 NVIDIA B200/B300 及 NVL72 机架的官方数据手册，数据可用性统计则来自 Epoch AI。

当我们提到 B200/B300 时，实际上指的是作为 NVL72 机架组成部分的 GB200/GB300 超级芯片。NVL72 的世界规模为 72 颗 GPU，这让训练这种级别的模型变得更加容易——因为这 72 颗 GPU 可以通过 NVLink/NVSwitch 高速互联，互相访问 HBM。

并行策略 caveat
仅做数据并行远远不够，你仍然需要其他并行策略（流水线并行、张量并行、序列并行）。为了计入所有瓶颈，我们假设 MFU（模型浮点利用率）仅为 20%。

3 前沿 MoE 模型的稀疏率
为什么 5% 是合理假设 已验证
  • DeepSeek V3/V3.2 (5.4%)、GLM-5 (5.4%) 和 MiniMax M2.5 (4.3%) 全部集中在 4%-6% 区间。5% 是这一范围的中心点。
  • Kimi K2.5 已达到 3.1%——趋势是走向更高稀疏度。对下一代模型来说，5% 是保守估计。
  • 较老的模型（Mixtral、DBRX）使用了约 27% 的激活比例。短短 18 个月内，行业迁移到了 3%-6%，这是一个决定性的转变。
  • DeepSeek V3 以 5.5% 激活比例在 14.8T Token 上成功完成训练，与稠密基线模型相比没有质量损失。
  • 5% 激活比例产生实用的模型尺寸：2T→100B、4T→200B、10T→500B 每 Token 激活量——都是已验证的架构规模。
4 训练计算量 (FLOPs)
计算量推导 公式

使用 MoE 时，每 Token 只计算激活参数：

Nactive = Ntotal × 0.05
C = 6 × Nactive × D
C = 6 × (Ntotal × 0.05) × (40 × Ntotal)
C = 12 × Ntotal²
最终简化为极其优雅的公式：C = 12 × Ntotal²，即训练计算量与总参数量的平方成正比，系数为 12。

6 计算链
六步推导流程 90 天训练窗口
// 假设训练窗口为 90 天
Step 1: Effective_FLOPS = Peak_FLOPS × 0.20
Step 2: GPU_seconds = C ÷ Effective_FLOPS
Step 3: GPU_hours = GPU_seconds ÷ 3,600
Step 4: GPUs_needed = GPU_hours ÷ 2,160 (= 90天 × 24小时)
Step 5: NVL72_Racks = GPUs_needed ÷ 72
Step 6: Total_Cost = GPU_hours × $/GPU/hr

11 合成数据生成成本
10T 模型的数据缺口 成本大头

10T 模型需要 400T Token，但互联网公开可用数据仅约 100T。剩余的 300T 必须通过合成方式生成。我们以 Claude Sonnet 4.6 作为代表性前沿 API 模型来分析生成成本。

生成 300T 合成 Token 的成本
假设输入输出比为 1:10（30T prompt token → 300T 生成 token）
// 标准定价
(30T ÷ 1M × $3) + (300T ÷ 1M × $15)
= $90M + $4,500M
= $4.6B

// 批处理定价（5折）
(30T ÷ 1M × $1.50) + (300T ÷ 1M × $7.50)
= $45M + $2,250M
= $2.3B

核心结论

本次思想实验的关键发现

2T 级别：完全可行
191 台 NVL72 机架，BF16 下 $148M。NeoLabs 这样的初创公司仍能承担。数据需求（80T）在现有互联网数据范围内。
4T 级别：可行但开始昂贵
762 台机架，BF16 下 $593M。需要约 60T 合成 Token 才能达到 160T 总量——可管理，但开始变得极其昂贵。
10T 级别：超大规模玩家的游戏
4,763 台机架，BF16 下 $3.7B。但 300T 合成 Token 额外增加 $2.3B（API 定价）或约 $75M（自研廉价模型）。
四大核心洞察
  • 合成数据可能与训练同价：按 API 定价，300T Token 经 Sonnet 4.6 生成花费 $2.3B——相当于 10T 级别模型 B200 BF16 训练成本 $3.7B 的近 60%。自研部署 cheaper 模型进行生成可能成为必需。
  • B300 仅在 FP4 下胜出：BF16 下吞吐量与 B200 相同但更贵 20%。据我所知，NVIDIA 将 B300 定位为推理卡，而非训练卡。
  • 数据才是主要瓶颈：不是算力或 GPU alone——10T 模型的 400T Token 需求可能是最难满足的约束条件！！！！
  • 稀疏度趋势利好：行业从 27% 激活率（Mixtral 时代）快速下降到 3-6%，让万亿参数模型的每 Token 激活量保持在已验证的架构规模内。
